# SLAM 궤적은 GT 보다 15.4% 짧다 — 그걸 재는 계측이 없었다

- id: finding/028 · date: 2026-09-04 · author: claude
- harness: omx · to: all
- subject: slam-path-length-vs-gt · supersedes: none
- topic: technique
- confidence: high · status: needs-experiment
- verified: 2026-09-04 · keywords: len_ratio, path-length, translation-compression, umeyama, drift-window, scale-ratio, instrumentation-gap
- summary: 채택 설정 shallow 재생에서 SLAM 경로 276.4 m 대 GT 326.7 m = len_ratio 0.846(15.4% 압축). 같은 런의 drift_window 0.916% · scale ratio 중앙 0.9949 는 둘 다 건강해 보인다 — scale ratio 는 ICP 를 자기 시드와 견주고 dist_total 은 GT 를 누적해서, 추정 궤적 자체의 길이를 재는 계측이 없었다. drift 가 못 보는 이유는 umeyama_se2 가 강체 정합이라 균일 축소를 흡수하기 때문(7% 압축 -> drift 2.04%, 3.4배 과소보고). 프로그램의 기존 추정 0.923(시드비 0.929 x ICP비 0.994)의 두 배이며 차이의 기전은 미확증(팩터그래프 최적화 / 오프라인 모집단 차이 후보). n=1.

## 무엇을 쟀나

`slam_accuracy_monitor` 에 SLAM 궤적 폴리라인의 길이(`dist_slam`)와 GT 대비 비
(`len_ratio`)를 넣고 채택 설정으로 shallow bag 을 재생했다
(`s14len-b_260904_055824`, `PROJECTION=altitude`, 그 외 기본).

| 양 | 값 |
|:--|--:|
| GT 경로 길이 `dist_total` | 326.7 m |
| SLAM 경로 길이 `dist_slam` | **276.4 m** |
| **`len_ratio`** | **0.846** |
| `drift_window` | 0.916% |
| `ATE_RMSE` | 2.992 m |
| `[INSTR] scale ratio` (fft, n=348) 중앙 | 0.9949 |
| `seed_dr` / `icp_attempted` | 4 / 352 |
| `feat_frames` | 10,865 / 11,135 (0.976) |

**궤적이 15.4% 짧은데 같은 런의 drift 는 0.916%, scale ratio 는 0.9949 다.**

## 왜 이 값이 어디에도 없었나

파이프라인의 두 길이 계측이 둘 다 다른 것을 잰다.

- `[INSTR] scale ratio` 는 **ICP 결과를 자기 시드와** 견준다
  (`core/slam.py:1364-1365`, `init_norm`=시드 · `est_norm`=ICP 결과). 시드가 이미
  짧으면 비율은 1.0 근처로 건강해 보인다.
- `dist_total` 은 **GT 를 누적**한다
  (`core/slam_accuracy_monitor.py:_accumulate_total_distance(gt_xy)`).

즉 추정 궤적 자체의 길이를 재는 계측이 없었다. 이 글의 처방은 그 한 줄을 넣은 것뿐이다.

## drift 지표가 왜 이걸 못 보나 — 기전

`_compute_ate_and_accuracy` 는 `umeyama_se2` 로 정합한 뒤 RMSE 를 낸다. 강체 정합이라
**균일하게 줄어든 경로도 회전·평행이동해 GT 위로 얹힌다.** 직선 100 m 를 0.93 배로
줄인 합성 입력에서 실측:

```
rmse = 2.0408 m,  gt_len = 100.0 m  ->  drift_window = 2.041%
```

7% 압축이 drift 2.04% 로 나온다 — **3.4 배 과소보고**. 회귀 가드는
`test_accuracy_monitor_drift.py::test_uniform_translation_compression_shows_up_as_the_length_ratio`.

## 프로그램의 기존 추정과 어긋난다

`HANDOFF.md` 미결 (1)은 압축을 두 단 곱으로 **≈ 0.923**(FFT 시드/실제 0.929 ×
ICP/시드 0.994)으로 추정했다. 종단 실측은 **0.846** 으로 그 두 배다.

⚠️ **차이의 기전은 미확증.** 후보 셋 — (a) 팩터그래프 최적화가 루프폐합으로 포즈를
더 당긴다, (b) 오프라인 0.929 는 고정 쌍 집합에서 잰 값이라 온라인 키프레임 스트림과
모집단이 다르다, (c) DR 폴백 구간의 기여. 이 런의 `seed_dr` 은 4/352 라 (c) 는 크지 않다.

## 경계 (이 계측을 쓸 때)

- **구간 정합.** GT 누적은 TF lookup 이 처음 성공한 traj 메시지부터 시작한다. 그
  시점의 SLAM 폴리라인 길이를 빼야 분자·분모가 같은 구간을 덮는다. 안 빼면
  브리지를 재생 2 분 뒤 띄운 런이 `len_ratio` **79.3** 을 낸다(실측).
- `keyframe_stride > 1` 이면 폴리라인을 건너뛰어 과소계산하므로 `nan` 을 낸다.
- 위 표의 0.846 은 `276.4 / 326.7` 이다. 그 런의 로그에 찍힌 값은 0.8424 로,
  오프셋을 한 샘플 늦게 잡던 버전이라 1.1 m 만큼 낮다(수정 후 커밋 `af46ae8`).
- **n=1.** 복제 미측정.
