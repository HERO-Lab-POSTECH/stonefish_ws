# 경로 커버리지 공백 — 값이 아니라 도달 가능성이 깨지는 결함

- harness: omo · to: all
- subject: path-coverage-gaps · supersedes: none
- topic: pattern
- confidence: high · status: resolved
- verified: 2026-09-01 · keywords: instrumentation, testing, ast, reachability, adversarial-review, slam
- summary: Phase 3 여섯 브랜치의 결함이 전부 '코드는 맞는데 거기로 가는 길이 없는' 부류였다. 계측이 자기 질문에서만 침묵한 사례, AST 배선 테스트가 통과하며 죽는 구멍 3종, write-only 플래그가 로그를 거짓말하게 만든 사례 — 셋 다 값 검사로는 안 잡힌다. 다음 사이클용 규칙 4개와 판별력 확인법 포함.

Phase 3 여섯 브랜치에서 나온 결함 중 **값이 틀려서 잡힌 것은 하나도 없었다.**
전부 코드는 멀쩡한데 **그 코드로 가는 길이 없는** 부류였다. 값 검사는 코드가
실행된다는 것을 전제하므로 이 부류에 구조적으로 눈이 멀다.

## 세 사례

**1. 계측이 자기 질문에서만 침묵했다** (`slam.py`, 세션 자체 발견 → agy 독립 확인)

`_log_instrumentation()` 이 ICP 경로 끝에만 있었는데
`add_sequential_scan_matching` 은 `if not ret.status:` 로 조기 return 한다.
`ssm.enable: false` 면 매 키프레임이 그 경로로 빠진다 — 그런데 **그 상황이 바로
I1(`ssm_disabled_count`)이 답해야 할 질문**이었다. 계측의 출발점이 자기가 필요한
유일한 구성에서만 아무것도 내지 않았다.

**2. AST 배선 테스트가 통과하면서 죽을 수 있는 구멍 3종** (codex 적대 검증)

| 구멍 | 왜 통과하나 | 좁힌 방법 |
|:--|:--|:--|
| 카운터 갱신 검사가 **읽기까지 인정** | 로그 한 줄이 `self.instr['k']` 를 읽으므로, 증가시키는 곳이 사라져도 "살아 있다" 고 증언한다 | `AugAssign` 대상만 갱신으로 센다 |
| 반환 dict 키를 **모듈 전체 dict 합집합**으로 검사 | 서로 다른 반환 경로가 서로를 가려 준다 — 어느 한 반환도 소비 조합을 다 싣지 않는데 통과 | 성공 반환 dict **하나**가 통째로 만족하는지 본다 |
| 검사가 **메서드 안만** 봄 | 콜백에서 호출 한 줄을 지우면 메서드도 계측도 온전한 채 영영 실행되지 않는데 전 항목 통과 | 호출자 존재 테스트를 따로 둔다 |

**3. `fft_is_dr_fallback` 이 write-only 였다** (I4)

쓰기만 있고 읽는 코드가 없어 DR fallback 시드에도 `[FFT_SEED]` 태그가 붙었다.
**로그가 거짓을 말하고 있었고**, 그 로그를 근거로 "DR seed 17%" 라는 보고가 나갔다.

## 왜 세 개가 같은 결함인가

셋 다 **도달 가능성(reachability)** 의 문제다. 1은 실행 경로가 로깅에 닿지 않았고,
2는 검사가 실행 경로를 안 봤고, 3은 데이터가 소비 지점에 닿지 않았다. 어느 것도
"값이 틀렸다" 로는 드러나지 않는다.

## 다음 사이클에 쓸 규칙

- **종료 경로를 블록 구조로 걷는다, 라인 번호로 비교하지 말 것.** 라인 번호 비교는
  앞선 블록의 호출 하나가 뒤따르는 모든 조기 return 을 가려 준다 — 두 번째 조기
  return 에서 호출을 빼도 통과한다.
- **"메서드 안에 있다" 와 "실행된다" 는 다른 주장이다.** 안쪽을 고정하는 검사에는
  바깥쪽 호출자 검사를 짝지어 붙인다.
- **집합 검사는 합집합이 아니라 대표 원소 하나로.** 여러 반환 경로가 있는 함수의
  계약을 합집합으로 검사하면 검사가 항상 통과하는 쪽으로 수렴한다.
- **판별력은 변이로 확인한다.** 이번 세 강화 전부 `git archive HEAD` 로 뽑은 사본
  트리에 변이를 넣어 실제로 실패하는지 봤다 — repo 를 안 건드리는 방법이다.

## 계측 특유의 함정 (실기 sign-off 때 읽을 것)

계측은 값을 세기만 하므로 **정적으로 판정할 수 있는 것이 배선의 존재뿐**이고,
숫자의 의미는 실행 구성에 딸려 온다. `slam` `P4_FLAGS.md` 의 "숫자를 읽을 때의
함정" 에 둘을 등재했다 — I11 의 표본이 조용히 걸러지는 것, `validate_with_odom:
false` 에서 I8~I10 이 통째로 침묵하는 것. 그리고 I1 의 sign-off 조건은
`키프레임 총수` 가 아니라 **`총수 - 1`** 이다(첫 키프레임은 prior 만 넣고 SSM 을
부르지 않는다). 이 정정이 없었으면 실기에서 "하나 모자라니 가설이 틀렸다" 로
오독될 것이었다.

## 부수 관찰 — 2-family 게이트

같은 프롬프트·같은 커밋으로 codex 와 agy 를 돌린 두 번 모두 **겹침이 0** 이었다
(sim `chore/dead-code-cleanup`: agy 0 · codex 5 / slam `feat/loc-instrumentation`:
agy 4 · codex 7). 세 번 연속 같은 패턴이라 벤더 품질 차이보다는 **같은 프롬프트가
모델마다 다른 축을 훑는다** 는 쪽에 가깝다. 표본이 작으므로 게이트를 여는 근거로만
쓰고 벤더별 강점 프로파일로 읽지 않는다.
