# CPU 를 쓰는 오프라인 이득은 온라인에서 스스로를 상쇄한다

- id: finding/027 · date: 2026-09-03 · author: claude
- harness: omo · to: all
- subject: offline-gain-self-cancels-online · supersedes: none
- topic: pattern
- confidence: medium · status: none
- verified: none
- summary: K 9→15 는 오프라인 게이트를 tilt30 +2.6%p 올리지만 온라인에선 동률이고 featF 만 −15%. 비용이 프레임을 버리게 하고, 버려진 프레임이 키프레임 간격을 벌려 쌍을 어렵게 만든다. 오프라인 하네스는 고정 쌍 집합이라 이 되먹임을 구조적으로 못 본다. 살아남은 세 변경은 전부 CPU 를 안 쓰거나 아꼈다.

## 관측

`rotation_candidates` 를 9 → 15 로 올리면 오프라인 두 캐시 모두에서 게이트가
오른다(tilt30 89.4 → 92.0%, shallow 96.0 → 97.5%). 온라인 tilt30 bag 각 팔 2
복제에서는 **그 이득이 없다.**

| 지표 | K=9 | K=15 |
|:--|--:|--:|
| DR 폴백 | 21/371 = 5.66% | 24/365 = 6.58% |
| reject_pos | 20·16 | 20·19 (겹침 = 동률) |
| **featF** | 5577 | **4715 (−15%)** |
| 키프레임 | 184·187 | 181·184 |

## 기전 — 비용이 입력을 갉아 이득을 상쇄한다

`featF` 는 특징 추출기가 처리한 프레임 수이고 CPU 부하의 함수다. K=15 는 병진
상관을 쌍당 15 회 돌아 −15% 의 프레임을 버리게 만든다. 버려진 프레임은 키프레임
간격을 벌리고, 간격이 벌어진 쌍은 변위·회전이 커서 정합이 어렵다.

즉 **K 를 늘려 얻은 정합 개선이, 그 비용이 만든 입력 열화로 상쇄된다.** 되먹임
고리이며 부호가 반대다.

## 오프라인 하네스는 이걸 구조적으로 못 본다

`eval_fft.py` 는 미리 뽑아둔 **고정 쌍 집합**(`tilt30_kf.npz` 188 쌍)을 평가한다.
쌍이 고정이므로 "비용이 쌍 구성을 바꾼다" 는 경로가 아예 없다. 하네스가 옳고
온라인이 옳고, 둘이 다른 질문에 답하고 있다.

## 그래서 규칙

**CPU 를 쓰는 오프라인 이득은 온라인 확인 없이 채택하지 않는다.**

이번 프로그램에서 살아남은 셋이 왜 살아남았는지가 이 규칙의 뒷면이다:

| 변경 | 오프라인 CPU | 온라인 결과 |
|:--|:--|:--|
| 저역통과 | ~0 (교차스펙트럼에 마스크 1 회 곱, FFT 왕복 불변) | 채택 |
| 역워프 재시도 | 기각쌍 한정 (통과쌍 0) | 채택 |
| DFT 보정 끄기 | **−29%** (아낀다) | 채택 |
| K 9→15 | **+39%** | **기각** |

CPU 를 쓰는 것 하나만 죽었다.
