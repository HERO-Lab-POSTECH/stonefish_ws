`slam_loop_robust_c`(Cauchy 커널 폭)를 양방향으로 밀어 **궤적 압축이 오차의 원인인지**
검정했다. **양방향 모두 기각이다.** 압축은 c 에 단조로 반응하는데 오차는 양끝에서 다
나빠지므로, 압축은 원인이 아니라 동반 현상이다.

## 왜 이 손잡이인가

finding/041 이 척도 축을 닫으면서 남긴 오차원은 뒤쪽이었다 — 궤적 길이비
`len_ratio` 0.9254 대 ICP-GT 0.9541. 즉 추정 궤적이 참보다 7~8% 짧고, 이건 RViz 에서
눈으로도 보인다. 백엔드에서 이 압축을 직접 쥐는 건 루프 팩터의 robust 커널 폭
`slam_loop_robust_c` 다: c 가 작으면 큰 잔차가 세게 억제돼 루프가 궤적을 덜 당기고,
c 가 크면 루프가 세게 당긴다. 압축이 원인이라면 c 를 키워 압축을 늘리거나 줄여
압축을 없앨 때 **한쪽 방향으로** 오차가 좋아져야 한다.

## 판정

**c=8.0 은 ATE 완전분리로 기각이다.** 세 반복 최소 2.889 가 기준선 최대 2.670 보다
크다(n=3 대 3 → p=0.05). 2D 는 완전분리가 아니다(2.668 < 2.824).

**c=1.0 은 완전분리에 못 미치지만 역시 기각이다.** 2D 최소 2.812 가 기준선 최대
2.824 에 0.012 m 차이로 걸려 분리가 깨지고 ATE 도 최소 2.572 가 기준선 최대 2.670
아래다. 통계적 유의는 없지만 두 축 다 나쁜 쪽이고 이득 방향이 하나도 없어, 판정
규칙 (a) 오차 우선에서 채택 근거가 성립하지 않는다.

**따라서 채택 config 의 c=3.0 이 이 축의 국소 최적이다.** 변경 없음.

## 확정된 기제 — len_ratio 는 c 에 단조다

압축비는 c 에 깨끗하게 단조로 반응한다: 중앙값 .9413 (c=1) → .9254 (c=3) → .8530
(c=8). 손잡이 하나로 압축을 ±0.07 움직일 수 있고, 세 조건의 len_ratio 구간이 서로
겹치지 않는다. 즉 **압축은 제어 가능한 양이며, 못 고쳐서 안 고친 게 아니다.**

그런데 오차는 압축에 단조가 아니다. 압축을 없애는 쪽(c=1, len_r 0.94)도, 더 세게
누르는 쪽(c=8, len_r 0.84)도 기준선보다 나쁘다. 해석은 하나다 — **궤적을 압축하는
그 루프 당김이 동시에 절대 드리프트를 보정하고 있다.** c=1 은 당김을 빼서 길이비를
예쁘게 만들지만 그 대가로 절대 위치가 흐른다(2D 악화). c=8 은 과당김이라 모양 자체가
깨진다(ATE 악화, 완전분리). 압축은 보정의 부산물이지 결함이 아니다.

**사용자 관점의 함의**: RViz 에서 보이는 7~8% 궤적 압축을 줄이는 것 자체는 성능
개선이 아니다. 줄이면 정확도가 나빠진다. 이건 finding/041 에서 척도 부족분을 1 로
끌어올릴수록 오차가 나빠졌던 것과 **같은 형태의 결론**이다 — 눈에 띄는 양을 옳아
보이는 방향으로 움직이는 것과 정확도를 올리는 것은 다른 일이다. 두 축에서 독립적으로
같은 패턴이 나왔다.

## 부수 관측

**DR 은 c 에 반응하지 않는다.** c=1 {0.00, 0.00, 0.28} · c=3 {0.28, 0.29, 0.57} ·
c=8 {0.00, 0.00, 0.57} 로 방향이 일관되지 않는다. 예상대로다 — c 는 백엔드 커널이고
DR 폴백은 프론트엔드 검증 게이트가 정한다. 세 조건 다 DR 0.6% 이하로 제약 2(DR
최소화)를 위반하지 않는다.

**`nssm.min_st_sep=8` 은 효과 없음으로 기각**(같은 배치, 3 반복 유효분): 2D 2.679 ·
2.664 · 2.531, ATE 2.984 · 2.725 · 2.300, DR 0.57 · 0.85 · 0.29, pcm 308 · 311 · 295.
2D 는 기준선과 겹치고 ATE 는 오히려 위쪽으로 치우친다. 후보 분리 하한을 키워도
루프 품질이 올라가지 않는다.

## 한계

Cauchy 폭 하나만 쓸었다. 백엔드의 나머지 손잡이 — 루프 후보 선정 기준, NSSM top-N,
ICP fitness 게이트, 프라이어 공분산 — 는 건드리지 않았다. "압축이 원인이 아니다" 는
결론은 압축을 c 로 움직였을 때의 것이고, 다른 기제로 압축을 바꾸면 다른 궤적을 그릴
수 있다. 다만 그 경우에도 목표는 압축 감소가 아니라 오차 감소여야 한다.
